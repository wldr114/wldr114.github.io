起因

折腾博客的时候看到一个给 DeepSeek Harness Web 做的皮肤插件 dsh-neco-arc，效果是 6 只 Neco-Arc 猫猫动图漂浮在页面上，可以拖动、缩放、调速，还有一个 mika 头像做角标。觉得很有意思，就想把这套东西搬到自己的 Hexo 博客上。

这篇文章记录一下从「读别人代码」到「移植到自己博客」的完整过程，以及踩的几个坑。

拆解 dsh-neco-arc 的实现

先读了一遍源码，它的结构很清晰：

  • host 侧（lib/index.js）：起一个静态资源路由 /neco-arc/*，只放行白名单里的文件（1.gif~`6.gif、mika.jpg、精灵图等），顺手把页面 favicon 换成 mika.jpg`。
  • client 侧（client/client.js）：注入一段 <style> + 用 React 在几个 slot 里渲染动图层、设置面板、侧栏开关。

核心思路有三层：

  1. 背景：整页背景图 + 半透明 token，让皮肤氛围透出来。
  2. 精灵图：6 张动图不是直接放 GIF，而是用 PNG 精灵图（sprite sheet）+ CSS steps() 播放，这样才能调播放速度（GIF 的速度是写死的，改不了）。
  3. 交互：拖拽用 Pointer Events 的 setPointerCapture，位置/大小/速度/可见性全部存 localStorage。

精灵图播放的原理就是：

  • 每只猫的动画帧水平拼成一张长图（比如 1 号猫 10 帧拼成 1440×163 的 PNG）。
  • 用一个 div 把这张长图设为背景，background-size 拉成 帧数 × 单帧宽。
  • 通过移动 background-position 来切换显示哪一帧。

移植到 Hexo

我的博客是 Hexo + archer 主题，没有 React 那套 slot 机制，所以直接用原生 JS 重写了一遍客户端逻辑，主题模板里只注入一个 <script> 和一个 <link>。

踩坑记录

坑一：GIF 调不了速

一开始图省事直接放 GIF，结果发现 GIF 的播放速度是文件里写死的，CSS/JS 都改不了。要调速只能换成精灵图自己控制切帧节奏。

坑二：CSS 动画的兼容性

最早照搬插件的 CSS steps() + @keyframes 方案，本地和线上 DOM 检查都正常（背景图、尺寸、动画名都在），但实际渲染就是出不来图。最后改成 **requestAnimationFrame 直接驱动 background-position**，彻底不依赖 CSS 动画，问题解决：

一个 rAF 循环统一驱动 6 只猫，state.speed 每帧实时读取，改速度立即生效。

坑三：localStorage 残留状态

有一版做了个设置面板，里面能「全部隐藏」。后来把面板删了，结果用户强刷后所有动图都不见了——因为旧的 localStorage 里存着 visible: false，新版还在读。解决方式是给存储 key 加版本号（neco-arc.state.v3），旧状态直接作废。

坑四：藏起来就找不回来

动图 × 掉或者拖出屏幕之后，悬停不到它就没法操作。于是加了一个固定左下角的「恢复 ARC」按钮，一键把所有动图/角标复位（显示、位置、大小、速度全回默认）。

最终效果

  • 6 只 Neco-Arc 动图 + 1 个 mika 角标 漂浮在博客页面上，位置沿边缘排布，不挡正文。
  • 每个元素都能：拖动改位置、**+/−** 缩放、**1×** 循环调速（0.5×→3×）、**×** 隐藏。
  • 「恢复 ARC」按钮 一键复位。
  • 所有状态存 localStorage，刷新不丢。
  • favicon 换成了 mika，右下角有 mika 圆形角标。

总结

整个过程其实就是「读一个成熟实现 → 抽离核心思路 → 用更简单的技术栈重写 → 踩坑 → 修」。几个体会：

  1. 精灵图 + 手动切帧是控制动画速度的关键，直接上 GIF 就锁死了。
  2. CSS 动画很优雅，但遇到兼容性问题时，requestAnimationFrame 手动驱动是最稳的兜底。
  3. 前端状态持久化一定要考虑「版本迁移」，否则改版后老数据会反过来坑你。
  4. 所有「能藏起来」的东西，都得留一个「能找回来」的入口。

代码都在博客仓库里，感兴趣可以看看 source/neco-arc/ 下的实现。
